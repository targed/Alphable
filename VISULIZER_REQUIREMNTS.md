# Alphable Replay Visualizer (ARV) - Requirements Specification

## 1. Executive Summary
The Alphable Replay Visualizer (ARV) is a graphical interface designed to render game logs generated by the Alphable AI engine. Its primary purpose is to allow human observers to analyze the strategic decision-making of the AlphaZero agents by scrubbing through game states, viewing potential candidate moves, and analyzing game statistics in a broadcast-quality format.

## 2. Functional Requirements

### 2.1 The Game Board View
*   **REQ-101: Grid Rendering:** The center of the screen must render a 15x15 Scrabble grid.
*   **REQ-102: Premium Squares:** The grid must distinctly color-code premium squares (TW=Red, DW=Pink, TL=Blue, DL=Light Blue) when empty.
*   **REQ-103: Tile Rendering:** Tiles must be rendered as rounded squares with high contrast (e.g., Tan background, Black text).
*   **REQ-104: Move Highlighting:** The most recently placed word must be visually highlighted (e.g., a glowing border or brighter tile color) to distinguish it from existing board tiles.
*   **REQ-105: Coordinate System:** The board edges must display 1-15 (rows) and A-O (columns) for easy reference.

### 2.2 Player Heads-Up Display (HUD)
*   **REQ-201: Player Panels:** Two distinct areas (Left/Right or Top/Bottom) must represent Player 0 and Player 1.
*   **REQ-202: Score Display:** Current score must be displayed prominently.
*   **REQ-203: Score Delta:** When a move is played, a "floating text" animation (e.g., `+42`) must appear to show the points gained.
*   **REQ-204: Rack View:** The player's current rack (7 tiles) must be visible. Hidden/Unseen tiles (opponent's rack) should be toggleable (Show/Hide) for "Perfect Information" analysis.
*   **REQ-205: Avatar/Identity:** Placeholder for Bot Name/Version (e.g., "AlphaZero Step-2000").

### 2.3 The "Broadcaster" Features (Will Anderson Style)
*   **REQ-301: Word Definition:** When a move is played, the definition of the primary word should appear in a dedicated corner box (requires connecting to a dictionary definition API or local database).
*   **REQ-302: Bag Tracker:** A visual representation or count of tiles remaining in the bag (e.g., "Tiles Left: 43").
*   **REQ-303: Probability/Evaluation Bar:** A bar at the bottom showing the AI's win probability (Value Head output) for the current state (e.g., 60% Blue vs 40% Red).

### 2.4 Playback Controls
*   **REQ-401: Timeline Slider:** A scrubbable progress bar representing the turns (0 to End).
*   **REQ-402: Transport Controls:** Buttons for:
    *   `<<` (Jump to Start)
    *   `<` (Previous Move)
    *   `Play/Pause` (Auto-advance turns every X seconds)
    *   `>` (Next Move)
    *   `>>` (Jump to End)
*   **REQ-403: Playback Speed:** A selector to adjust auto-play speed (0.5x, 1x, 2x, 5x).

### 2.5 Move Log & Statistics Panel
*   **REQ-501: Move List:** A scrollable side panel listing every move in standard notation (e.g., `1. 8H  REDOX  42`). Clicking a line jumps the board to that state.
*   **REQ-502: End-Game Stats:** A summary modal appearing at the end of the game showing:
    *   Total Bingos per player.
    *   Average score per turn.
    *   Number of invalid/passed moves.

## 3. Technical Architecture

### 3.1 Data Source
*   **Input Format:** The Visualizer will consume `.json` game logs generated by the `scrabble.py` engine.
*   **Log Structure:**
    ```json
    {
      "game_id": "uuid",
      "final_score": [300, 320],
      "turns": [
        {
          "turn_index": 0,
          "player": 0,
          "action_type": "PLAY",
          "word": "HELLO",
          "position": [7, 7],
          "direction": "Across",
          "score": 24,
          "rack_before": ["H", "E", "L", "L", "O", "X", "Y"],
          "board_state_after": "..." (Optional, or re-simulated)
        }
      ]
    }
    ```

### 3.2 Backend (Python)
*   **Framework:** Flask or FastAPI.
*   **Role:**
    *   Parses the raw `learner.jsonl` or specific game logs.
    *   Serves the JSON data to the frontend.
    *   (Optional) Runs the Engine (`scrabble.py`) on-demand to calculate "What if" scenarios if the user clicks a different square.

### 3.3 Frontend (React/TypeScript)
*   **Board Component:** CSS Grid or HTML5 Canvas for rendering the 15x15 board.
*   **State Management:** Redux or React Context to handle the "Current Turn" pointer and update the board/racks instantly when scrubbing the timeline.

## 4. Implementation Plan

### Phase 1: The Logger
Modify `scrabble.py` to export a full game history JSON file at the end of every evaluation match (not training games, just evaluation games).

### Phase 2: The Viewer (MVP)
Build a basic web page that loads one JSON file and lets you click "Next/Prev" to see the board update.

### Phase 3: The Polish
Add the "Will Anderson" features: CSS animations for tiles placing, the score ticker, and the definition lookup.

### Phase 4: The Dashboard
Create a menu to select which game to watch from the `scrabble_az_checkpoints` folder.
