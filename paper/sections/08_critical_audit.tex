\section{Critical Audit: Parameter Ceilings and Limitations}
\label{sec:critical_audit}

Scientific rigor requires an adversarial audit of baseline configurations. Extraordinary claims require extraordinary evidence: is \algo's edge a true universal superiority over \magpie, or does it hold strictly against an unoptimized default?

\subsection{The Unturned Parameter Ceiling of Native MAGPIE}

A source-level code audit of the \magpie\ engine (`vendor/magpie/src/`) reveals that the standard baseline designated as ``Base \magpie'' in literature operates in an unoptimized, 1-ply static greedy mode with all advanced simulation and positional modules disabled:
\begin{enumerate}
    \item \textbf{Positional Adjustment Terms (\texttt{-pat CSW24}):} A neural-linear evaluator assessing quadrant openness, vowel-consonant balance, and premium-square distances (\texttt{players\_data.c:48}, disabled by default).
    \item \textbf{High-Throughput PIMC Simulation (\texttt{PlayChooser}):} Native C simulation lookahead operating at $\sim 98,134$ rollouts/second (\texttt{config.c:215}, disabled by default).
    \item \textbf{Exact Alpha-Beta Endgame Solver (\texttt{-eplies}):} Minimax lookahead at zero bag (\texttt{endgame.c:85}, disabled by default).
\end{enumerate}

\subsection{Key Empirical Findings}

\begin{enumerate}
    \item \textbf{Unrealized Ceiling of Native MAGPIE:} Maximally tuned \magpie\ achieves a massive $+63.02$ pt advantage over default \magpie\ ($t = 4.54, p = 0.00022$). Default Base \magpie\ operates far below its achievable ceiling.
    \item \textbf{Bounding the Superiority Claim:} Claiming that \algo\ is unconditionally superior to ``\magpie'' is methodologically false. \algo's $+7.06$ pt advantage holds strictly against \textbf{1-ply Static KLV Base \magpie}. Against an unconstrained, deeply simulating Base \magpie\ running $\sim 98,000$ rollouts/sec in native C, \algo\ Champion incurs a $-46.48$ pt deficit.
    \item \textbf{Candidate Generator Transferability:} When \algo\ incorporates \texttt{-pat CSW24} into its native C candidate generator, the upgraded candidate beam alters $50\%$ of search decisions and yields an empirical $+2.05$ pt boost in head-to-head play (Matchup 4).
\end{enumerate}

\subsection{Architectural Trade-offs: C Simulation vs. Neural Inference}

Why does Tuned \magpie\ retain an advantage over 2-ply \bams? The answer lies in the fundamental engineering trade-off between compiled simulation throughput and neural inference depth:
\begin{itemize}
    \item \textbf{Compiled C Simulation:} At $\sim 98,000$ rollouts/second, a C engine can sample hundreds of thousands of full Monte Carlo trajectories within a standard 3-second tournament move limit, brute-forcing deep lookahead.
    \item \textbf{Python / PyTorch Neural Search:} \algo's 2-ply \bams\ search evaluates candidate moves with cross-attention value heads and Bayesian belief inference at $\sim 65.4$ ms per turn. While structurally superior at eliminating strategy fusion, 2-ply lookahead is constrained in depth compared to unconstrained asymptotic Monte Carlo rollouts.
\end{itemize}
This highlights the frontier for future research: compiling neural tensor operations directly into native C/C++ inference engines to unify deep valuation with massive rollout throughput.
